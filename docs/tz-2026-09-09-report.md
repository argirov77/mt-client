```
public/llms.txt:38   Operating days: Monday, Wednesday, Saturday
public/llms.txt:39   Peak season: May-September (daily departures sometimes available)
public/llms.txt:40   Off-season: 3 times per week
public/llms.txt:82   A: Direct bus with Maximov Tours. Departs Mon/Wed/Sat at 13:40, ...
```

Это прямое противоречие вставляемому тексту, и формулировки в ТЗ на них нет,
поэтому **ничего из перечисленного не тронуто**. Нужно ваше решение:

1. `llms.txt` устарел, дни в нём привести к ТЗ (среда/суббота из Одессы,
   понедельник/пятница в сторону Одессы) — тогда пришлите точный текст, как
   и для страниц;
2. либо Mon/Wed/Sat верны, а ТЗ описывает не всю картину — тогда надо
   пересматривать тексты по пункту 1.

Заодно там же: `## Last Updated: 2025-05-07` и время отправления `13:40`,
которого больше нигде на сайте нет. Проверять их в рамках этого ТЗ мы не стали.

## 3. Футер

`src/components/SiteFooter.tsx`:

```tsx
const COPYRIGHT_YEAR = new Date().getFullYear();
...
<p className="mt-2 text-slate-300" suppressHydrationWarning>
  © 2005–{COPYRIGHT_YEAR} ООО «Максимов Турс»
</p>
```

`2005` остался константой (год запуска сайта), конечный год считается от
текущей даты. Дефис заменён на тире, как в приёмке ТЗ (`© 2005–2026`).

`suppressHydrationWarning` — потому что страницы статические (`revalidate =
600`): в новогоднюю ночь год в отданном из кэша HTML может на несколько минут
отстать от года, который посчитает браузер. Это единственная точка, где SSR и
DOM могли бы разойтись; атрибут её закрывает.

Проверено на собранных страницах: `© 2005–2026` на всех 56.

## 4. Опечатка `пiсля` с латинской `i` — не сделано, нужен доступ к бэкенду

**Правка в этом репозитории невозможна.** Названия остановок в `mt-client`
нигде не хранятся: `Routes.tsx` рисует то, что приходит из
`POST /selected_route` (см. `src/lib/serverData.ts`), а тот проксируется на
бэкенд (`netlify.toml`: `/api/* → http://38.79.154.248/api/:splat`).

```
$ grep -rn "Сарата\|Татарубунар\|Тиха поляна\|Lukoil\|переїзду" src public
(пусто)
```

Ни фикстур, ни фолбэк-списка остановок в репозитории нет — ни одного названия
остановки. Строка «Зупинка пiсля переїзду» живёт в таблице `stop` на бэкенде,
и чинить её надо там (одно поле `name`, латинская `i` U+0069 → украинская `і`
U+0456).

**Выгрузить полный список названий остановок для отдельного решения по переводу
тоже не получилось:** из песочницы нет сетевого доступа к
`maximovtours.com` / `38.79.154.248` (прокси отдаёт 403, во время `next build`
все вызовы `/selected_route` и `/selected_pricelist` вернули HTTP 403).

Список выгружается одной командой с машины, у которой есть доступ:

```bash
for lang in ru ua en bg; do
  curl -s -X POST https://maximovtours.com/api/selected_route \
       -H 'Content-Type: application/json' -d "{\"lang\":\"$lang\"}" \
  | python3 -c "
import json,sys
d=json.load(sys.stdin)
for side in ('forward','backward'):
    for s in (d.get(side) or {}).get('stops',[]):
        print('$lang', s['id'], repr(s['name']), repr(s.get('description')))
"
done | sort -u
```

`repr()` здесь важен: он покажет смешанную раскладку явно, иначе латинская `i`
от украинской `і` на глаз не отличается.

Подтверждение, что вхождений нет на клиенте:

```
$ grep -rn $'пiсля' src public
(пусто)
```

## 5. Description: разведка

### 5.1. Откуда шаблон берёт `title` и `description`

Единственный механизм — `generateMetadata` в App Router, данные — статические
объекты в коде. Никаких Markdown, CMS и внешних источников.

| Страницы | Точка входа | Функция | Данные |
|---|---|---|---|
| `/`, `/ua`, `/en`, `/bg` | `src/app/[locale]/(site)/page.tsx:24` | `buildHomeMetadata(locale)` (`src/lib/seo.ts:107`) | `HOME_META` — `src/lib/seo.ts:84` |
| 52 страницы маршрутов и хаб | `src/app/[locale]/(site)/[trip]/page.tsx:35` | `buildTripMetadata(key, locale)` (`src/lib/seo.ts:134`) | `tripsData[key].i18n[locale].title` / `.description` — `src/lib/tripsData.ts` |
| фолбэк корневого layout | `src/app/[locale]/layout.tsx:25` | статический `export const metadata` | `HOME_META.ru` |
| служебные (`/booking`, `/cabinet`, `/return`, `/ticket/*`, `/purchase/*`, `/q/*`) | статические `export const metadata` в своих файлах | — | литералы в тех же файлах |

Те же строки идут в OG и Twitter-карточки (`openGraph.title/description`,
`twitter.title/description` в обеих функциях) — то есть правка одного поля
`i18n[locale].description` меняет сразу три места.
